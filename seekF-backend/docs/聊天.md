# 用户私聊

用户从其他用户主页点击“发消息”，通过 `/chat?userId=...` 打开消息页。消息页只提供聊天记录搜索，不提供联系人、加好友、群聊或电话入口。

## 接口

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| POST | `/user/session/openSession` | 打开或恢复当前用户与目标用户的私聊，提交 `receive_id`，返回 `session_id` |
| POST | `/user/session/getSessionList` | 获取当前用户的私聊列表，AI 会话使用独立接口 |
| POST | `/user/session/deleteSession` | 删除当前用户的会话 |
| POST | `/user/session/checkOpenSessionAllowed` | 校验目标及双方用户状态 |
| POST | `/user/message/getUserMessageList` | 分页读取参与者之间的私聊记录 |
| POST | `/user/message/search` | 搜索自己的私聊会话记录 |
| POST | `/user/message/searchSuggestions` | 查询自己的私聊消息联想 |
| GET | `/user/ws/login?client_id=...` | 建立 WebSocket，编号必须与登录身份一致 |
| POST | `/user/ws/logout` | 断开当前登录用户的连接 |

接口均需要登录。默认 Redis 认证使用后端设置的 HttpOnly `token` Cookie；JWT 模式使用 Authorization Header。

## 消息与投递

WebSocket 只接受当前用户发送给其他 `U` 前缀用户的消息：`type=0` 为文字，`type=2` 为文件。会话必须属于发送者并对应接收者，双方不能被禁用。私聊不依赖好友关系，也不再查询旧联系人表。

请求包含 `session_id`、`send_id`、`receive_id`、`type` 及对应文字/文件字段。响应包含 `uuid`，供前端历史记录和实时回显去重。双方各自持有一个会话编号，接收端按对方用户编号匹配会话。

前端每 25 秒发送 `{"type":"ping"}`，服务端返回 pong。文本和文件消息经已有 Kafka 聊天主题持久化并向双方投递，收到离线消息后由会话列表和历史记录恢复。

## 数据与迁移

`message` 保存用户私聊与 AI 对话共用的消息，`session` 保存用户私聊及 AI 会话。群、联系人及申请表和通话字段已删除，不再提供对应模型或业务接口。

实施与数据库验收记录见 [私聊精简计划](../../plan/private-chat.md)；执行方式和备份说明见 [迁移说明](../../plan/private-chat/database-cleanup.md)。迁移脚本位于 `scripts/migrations/private-chat/`，从后端根目录运行，不启动业务服务。
